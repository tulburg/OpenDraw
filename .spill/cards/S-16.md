## Purpose
Review in Paper happens in comment threads pinned to layers, and agents read them with `list_comment_threads`, `get_comment_thread`, `set_comment_thread_status` and `list_comment_thread_authors` to act on feedback and mark it done. OpenDraw has no comments. Everything is local, so the authors are the local user and agents.

## Requirements
1. A file stores comment threads, saved with it: each thread is pinned to a node (or a point on the page canvas), with a status (`open` or `resolved`), created and updated times, and messages. Each message has an author (user ID and display name), text, a time, and optional emoji reactions.
2. The local user has a display name (asked once, changeable in a small settings popover in the top bar) and the user ID `local-user`. Agents never write comments; they only read them and change status.
3. A Comment tool (C) in the toolbar places a pin: clicking a layer pins the thread to it, clicking empty canvas pins it to that point. Pins show on the canvas and follow their layer when it moves. A thread's popover shows its messages, a reply box, Resolve or Reopen, and Delete for its author.
4. A Comments panel (a tab beside Layers and Tokens) lists threads by page with status, author, a preview and reply count; it filters open, resolved or all and searches text. Clicking a thread selects its layer and opens it.
5. Deleting a layer leaves its threads, pinned to where the layer was. Deleted threads and messages are never returned by any tool.
6. MCP tools with Paper's names and arguments: `list_comment_threads` (pageId, currentPageOnly, nodeId, status defaulting to open, participantUserId and threadAuthorUserId with `current-user` meaning the local user, search and searchScope, sortField page/createdAt/updatedAt, sortDirection, limit, offset, previewLength); `get_comment_thread` {fileId, commentThreadId} with all messages, reactions, page and node context; `set_comment_thread_status` {fileId, commentThreadId, status}; `list_comment_thread_authors` {fileId, pageId?} with message and thread counts and last activity.
7. A status change from an agent shows on the canvas at once and is one undo step for the user.

## Out of scope
Multiple people, mentions and notifications, attachments, comments in exports.

## Acceptance checks
- Placing a comment on a layer with the Comment tool, replying, and resolving it work in the app, and the thread survives a restart.
- `list_comment_threads` returns only open threads by default; `status: "all"`, `nodeId`, `search` and `currentPageOnly` filter as described; `limit` and `offset` page through them.
- `get_comment_thread` returns every message with author and time; `set_comment_thread_status` resolving a thread removes its pin from the open view in the app.
- `participantUserId: "current-user"` matches threads the local user wrote in; `list_comment_thread_authors` counts them.
- Moving a layer moves its pins; deleting it keeps the thread at the old position.
