## Purpose
OpenDraw runs only from a dev checkout, and connecting a coding agent means knowing where the stdio bridge lives. It should install like an app and tell the user how to connect Claude Code (or any MCP client) in one step.

## Requirements
1. A build command produces an installable macOS app (universal or per-architecture) and a DMG, with the app name, an app icon of our own, and the version from package.json. Windows and Linux builds are produced by the same command when run on those platforms.
2. The packaged app runs the MCP server and ships the `opendraw-mcp` bridge inside the bundle, runnable with the bundled Node runtime (Electron as Node), so users need no separate Node install.
3. A Connect an agent dialog (Help menu and a button on the home view) shows the exact command to add OpenDraw to Claude Code (`claude mcp add ...`) and the JSON for other MCP clients, each with a Copy button, using the paths of the running app. It shows whether an agent is connected right now.
4. An About window shows the version, the MCP server status and port, and the workspace folder.
5. The packaged app keeps its data (state, workspace default, logs) in the normal per-user locations, and the dev build keeps using its own so the two do not collide.

## Out of scope
Code signing and notarization (they need the user's certificates), auto-update, app store builds.

## Acceptance checks
- The build command produces a DMG; the app inside launches on a clean user profile and opens a new file.
- Running the copied `claude mcp add` command's bridge path with `--version` (or a tools/list request) against the packaged app returns OpenDraw's tools.
- The Connect dialog's command uses the installed app's paths, and it shows "connected" while the bridge is attached.
- The About window shows the version from package.json and the MCP port.
