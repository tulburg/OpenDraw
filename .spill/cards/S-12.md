## Purpose
A file can hold several pages, but there is no way to see or manage them in the app, and agents lack Paper's page tools. Users and agents need to add, rename, reorder and switch pages, as in Paper.

## Requirements
1. The layers panel has a page list above the layers: each page shows its icon and name, the current page is highlighted, and clicking a page switches to it (keeping each page's own viewport).
2. A + button adds a page after the current one, named "Page N", and switches to it. Double-clicking a page name renames it in place. A page's context menu offers Rename, Duplicate, Change icon and Delete; Delete asks for confirmation and is not offered for the last page.
3. Pages can be reordered by dragging in the list. Dividers (visual separators between groups) can be added from the context menu and dragged like pages.
4. Page icons follow Paper's set: arrow, padlock, check, cross, info, question, design, vector, images, table, presentation, blueprint, swatches, bar-chart, line-chart, pie-chart, paper; no icon shows the default.
5. MCP: `create_page` {fileId, name?, icon?} adds a page after the one the user is viewing and returns its ID without switching the user's page. `update_pages` {fileId, updates: [{pageId, name?, icon? (null restores the default)}]} renames and re-icons pages. `arrange_pages` {fileId, order, removeDividerIds?} takes the complete new order (page and divider IDs, plus `{type: "divider"}` for new dividers), rejects the call with no change if any ID is missing, unknown or repeated, never deletes pages, and returns the resulting list with new divider IDs.
6. `get_basic_info` lists pages and dividers in order with IDs, names and icons, and marks the page the user is viewing.
7. Every page change (add, rename, icon, reorder, divider, delete) is one undo step and is saved with the file.

## Out of scope
Moving layers between pages by drag, page thumbnails, per-page backgrounds, page-level comments.

## Acceptance checks
- Clicking + adds "Page 2" after the current page and shows it; clicking Page 1 switches back with its viewport unchanged.
- Renaming by double-click, reordering by drag and adding a divider are each one undo step and survive a restart.
- An agent's `create_page` adds a page without switching the user's page; `update_pages` sets a name and icon; `arrange_pages` with a missing ID is rejected and changes nothing; with a full order plus `{type: "divider"}` it reorders and returns the new divider's ID.
- `get_basic_info` reflects the new order, names, icons and dividers.
