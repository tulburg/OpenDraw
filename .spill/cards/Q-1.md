Open pencil is already a working editor: window, canvas, pan and zoom, selection, layers, undo, components, fonts, export, comments, collaboration and an MCP server. Paper's allowed CSS (flex, padding, gap; no margin, grid or tables) maps closely onto its auto-layout, so most Paper tools could be adapters over it. A new app starts with none of that, but CSS-native storage makes tools like get_computed_styles and write_html near-free. Picking A or B also settles Q-2 (Tauri) and Q-3 (Vue) unless we choose to switch.

- A. Fork open pencil, keep its core, and put Paper's CSS API on top. Fastest: most of S-2 exists on day one and most Paper tools become adapters. Cost: CSS stays a translation layer, so CSS outside Paper's subset (filters, transforms, some backgrounds) is lossy, and the CLAUDE.md rule that CSS is the stored format would be relaxed (recommended for speed)
- B. Fork open pencil, then replace its core with CSS-native storage piece by piece. A working app from day one, but a long migration through code built for the other model
- C. New CSS-native app, copying over open pencil's MCP server and useful parts. Cleanest model, but editor basics (undo, selection, layers, fonts, export) are rebuilt before Paper features land
