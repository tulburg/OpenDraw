## Purpose
A review of the built specs against Paper's tool schemas found two gaps. Agents need to place local images by absolute path, which OpenDraw refuses today (S-17 only takes paths inside the workspace). And `get_node_info` ignores layer locks (S-18). Local image URLs carry OpenDraw's own name: the scheme becomes `opendraw-asset://` instead of the `paper-asset://` S-17 used.

## Requirements
1. The local image scheme is `opendraw-asset://`. It takes absolute paths (`opendraw-asset:///Users/name/logo.svg`) and paths relative to the workspace, in `<img src>`, `background-image` and `update_styles`. Which files it may reach, and whether the image is copied into the file, follows Q-8.
2. `paper-asset://` URLs written by agents used to Paper are still accepted on input and stored as `opendraw-asset://`; files saved with `paper-asset://` URLs by S-17 load and are rewritten to the new scheme. Nothing outputs `paper-asset://` any more (`get_jsx`, the styles panel, HTML copy).
3. A path that does not exist or is not an image fails that write with a clear error naming the path; nothing is half-written.
4. Screenshots, exports, thumbnails and `get_fill_image` render these images like any other.
5. `get_node_info` reports `locked: true` for a layer locked in the layers panel, and for layers inside a locked one; today it always reports `false`.
6. Tool descriptions and the server instructions describe `opendraw-asset://` with absolute paths, in our own words.

## Out of scope
Generated images (S-25), remote URLs other than http(s), renaming other Paper-named identifiers (Q-10).

## Acceptance checks
- `write_html` with `<img src="opendraw-asset:///<absolute path to a PNG outside the workspace>">` renders on the canvas and in `get_screenshot`.
- The same with `paper-asset://` works and `get_jsx` returns `opendraw-asset://`.
- A file saved with an S-17 `paper-asset://` URL opens with the image showing.
- A missing absolute path returns an error naming it and changes nothing; paths outside the allowed area behave as Q-8 decides.
- Lock a layer in the panel: `get_node_info` on it and on its child reports `locked: true`; unlock reports `false`.
