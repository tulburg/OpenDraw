## Purpose
Every later feature (the MCP write tools, canvas editing, the styles panel) changes the document the same way. This spec builds that one path: a CSS-native node store with a small set of edits, undo and redo, and autosave, so nothing edits the document behind its back.

## Requirements
1. All document changes go through one edit API in the renderer: insert nodes (into a parent at an index), update styles (merge, with `null` removing a property), set text, rename, move (reparent and reorder), duplicate (new IDs for the whole subtree), and delete.
2. Each call is one transaction. Several edits can be grouped into one transaction, and a transaction that fails part-way changes nothing.
3. Style updates drop properties that are inert in the node's context and return them as `ignoredStyles`, following Paper: for example `margin` anywhere, `display: grid` or `display: inline` on containers, and `left`/`top` on a node that is not absolutely positioned or an artboard.
4. Undo and redo (cmd/ctrl + Z, shift + cmd/ctrl + Z) step through transactions, 200 deep, and restore the selection that went with each step.
5. The canvas, layers panel and styles panel re-render from the store after every change. The layers panel shows the full tree, not just artboards.
6. The file autosaves about 500 ms after the last change, with an atomic write. A quit or window close flushes a pending save first.
7. Node IDs stay stable across saves and reloads.

## Out of scope
Drawing tools, canvas handles (move and resize by mouse), editing styles from the panel, HTML import (S-5), multi-file undo.

## Acceptance checks
- Each edit in Req 1 changes the rendered DOM and the saved file as expected.
- A grouped transaction with one invalid edit leaves the document unchanged.
- `update styles` with `margin` and a valid `padding` applies padding and reports margin in `ignoredStyles`.
- 10 edits, then 10 undos, gives back the starting document exactly; 10 redos gives the final one.
- Selection follows undo and redo.
- Edit, wait 1 s, kill the app: the file on disk has the edit. Edit then quit immediately: the file has it too.
- Reload: the same node IDs come back.
