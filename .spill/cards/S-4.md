## Purpose
Agents (Claude Code and other MCP clients) connect to OpenDraw on this machine and read the open design, using the same tool names, arguments and result shapes as Paper's MCP server, so existing prompts and skills for Paper work unchanged.

## Requirements
1. While OpenDraw is running it serves MCP over Streamable HTTP on 127.0.0.1 only, and writes the endpoint to a discovery file in the app's data folder.
2. A stdio command (`opendraw-mcp`) forwards to that endpoint, so it can be added with `claude mcp add opendraw -- opendraw-mcp`. When the app is not running, every tool returns a clear "OpenDraw is not running" error.
3. Read tools with Paper's names and arguments: `get_basic_info`, `get_selection`, `get_tree_summary`, `get_node_info`, `get_children`, `find_nodes`, `get_jsx` (inline styles or Tailwind), `get_computed_styles` (from the browser, not the stored CSS), `get_screenshot` (PNG at scale 1 or 2).
4. `fileId` and `pageId` work as in Paper: the document's ID, defaulting to what the user is viewing.
5. Tool descriptions and errors are our own text. No Paper branding, names or wording.
6. The server's instructions tell the agent how OpenDraw's document model works (CSS-native, artboards, flex layout).

## Out of scope
Write tools (S-5), files and folders tools, tokens, comments, export, `get_guide` topics, remote access.

## Acceptance checks
- `claude mcp add` with `opendraw-mcp`, then each read tool returns correct data for a test document with nested frames and text.
- `get_computed_styles` on a flex child reports its laid-out width, not just its stored CSS.
- `get_screenshot` of an artboard matches the canvas pixels at scale 1.
- `get_jsx` round-trips: its output describes the same tree, styles and text as the document.
- The HTTP listener refuses connections from other hosts.
- With the app closed, a tool call returns the not-running error instead of hanging.
