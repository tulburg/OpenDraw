## Purpose
OpenDraw opens one file at a time from a fixed workspace folder. Paper lets users and agents browse, create, organize and archive files and folders, and open several files as tabs. OpenDraw needs a local equivalent, with Paper's resource tools working against it.

## Requirements
1. **Workspace.** Files and folders live as real `.opendraw` files and directories under the workspace folder. A small index (`.opendraw-index.json`) gives every file and folder a stable ID and keeps archive flags and created/updated times; files moved or added on disk by hand are picked up on launch.
2. **File browser.** A home view lists folders and files (newest first) with name, thumbnail and last edited time; it supports creating, renaming, moving (drag into a folder), archiving and restoring from an Archive view. A file can be opened from it.
3. **Tabs.** Open files show as tabs in the top bar; one tab is active. Tabs can be closed and reordered; open tabs are restored on launch.
4. **MCP tools**, with Paper's names and arguments:
   - `list_resources` {parentId?, includeArchived?, limit?}: open files first (marked `open`, and `active` for the foreground tab), then the most recently updated files and folders, each with type, id, name, parentId and timestamps; `truncated` when the limit cuts the list.
   - `create_file` {name?, parentId?, cloneFileId?} and `create_folder` {name?, parentId?} return id, name and parentId.
   - `move_resources` {resourceIds, parentId}, `rename_resource` {resourceId, name}, `archive_resources` and `unarchive_resources` {resourceIds}, each all or nothing as Paper describes.
   - `open_file` {fileId, pageId?} opens the file as a tab and returns a `get_basic_info` response; it does not switch the page of a file that is already open.
5. Every file tool (read and write) accepts the `fileId` of any open file, not only the active one, so agents can work in a background tab.
6. Names are trimmed and capped at 500 characters. Folder default name "Untitled project", file default "Untitled".

## Out of scope
Teams, sharing and permissions, drafts versus team space (everything is local), syncing, deleting files for good (archive only).

## Acceptance checks
- Creating a folder and a file in it through the browser and through `create_folder`/`create_file` both show up in `list_resources` with the right parentId, and as files on disk.
- `create_file` with `cloneFileId` makes a copy with the same pages and nodes and new IDs.
- `move_resources` with one invalid ID moves nothing; with valid IDs it moves them, folder contents included.
- Archiving a folder hides it and its contents from `list_resources` unless `includeArchived`; unarchiving restores them.
- `open_file` opens a second tab; `write_html` with that file's `fileId` edits it while the first tab stays in front.
- Open tabs and the active tab are restored after a restart.
