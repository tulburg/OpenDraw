## Purpose
Paper stores design tokens as typed CSS custom properties that any style can reference with `var(--name)`. OpenDraw has no tokens yet, so agents cannot build or reuse a design system. Tokens should stay plain CSS: the file stores them, the canvas applies them as custom properties, and styles keep the `var()` reference.

## Requirements
1. A file stores a list of tokens: `name` (a CSS custom property, `--x`), `type` (breakpoint, color, container, fontFamily, fontSize, fontWeight, letterSpacing, lineHeight, opacity, radius, spacing), `value`, and an optional `description` (max 1024 characters). A value can alias another token with `var(--other)`.
2. The canvas applies the tokens as custom properties on every artboard, so `var(--color-primary)` in any style renders with the token's value, and changing a token updates every layer that uses it.
3. MCP tools with Paper's names and arguments: `create_tokens` {fileId, tokens: [{type, name, value, description?}]} returns one result per entry (created or error); `get_tokens` {fileId, format?: json | css | tailwind, namePattern?, types?} lists tokens, as JSON, a `:root { ... }` block, or a Tailwind v4 `@theme { ... }` block; `set_tokens` {fileId, tokens: [{name, newName?, value?, description?, delete?}]} renames, updates or deletes, applied in order, with per-entry errors.
4. Renaming a token rewrites `var()` references to it in the file's styles and in other tokens. Deleting a token that is still referenced is allowed and reported, listing where it is used.
5. Values are checked by type: colors must be CSS colors, sizes px strings, fontWeight a number, opacity 0-1 or a percent. Invalid entries are rejected in-band without stopping the rest.
6. Styles keep `var()` as written: `write_html`, `update_styles` and the styles panel accept `var(--x)`; `get_jsx` and `get_node_info` return the reference; `get_computed_styles` returns the resolved value.
7. A Tokens panel (a tab next to Layers) lists tokens by type with swatches and values, and lets the user add, edit, rename and delete them. Color and number fields in the styles panel offer matching tokens, and a field using a token shows the token name.
8. Every token change is one undo step and is saved with the file.

## Out of scope
Token modes (light/dark themes), importing tokens from other files or from Figma, breakpoint-driven responsive layouts.

## Acceptance checks
- `create_tokens` with a color and an alias to it creates both; a frame styled `backgroundColor: var(--color-primary)` renders the token color.
- `set_tokens` changing the color re-renders every layer using it, in one undo step.
- Renaming `--color-primary` to `--color-brand` rewrites references in styles and aliases.
- `get_tokens` returns the same tokens as JSON, as a `:root` block and as a Tailwind `@theme` block; `namePattern: "--color-*"` filters.
- `get_jsx` shows `var(--color-brand)`; `get_computed_styles` shows the resolved color.
- An invalid color in `create_tokens` returns an error for that entry while the others are created.
- In the Tokens panel, editing a token's value updates the canvas; picking a token in a styles panel color field writes `var(--name)`.
