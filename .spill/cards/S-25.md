## Purpose
Paper lets agents write generated-image URLs (`paper-gen://`) anywhere an image URL goes; the app generates the image and fills it in. OpenDraw's scheme carries its own name: `opendraw-gen://`. Its tool descriptions tell agents to read an `image-generation` guide first, and `get_node_info` reports generation status. OpenDraw left this out (S-5, S-17), so a Paper-trained agent asked for generated imagery gets a broken image. This is the last Paper feature missing from the MCP surface besides video export.

## Requirements
1. `opendraw-gen://` URLs are accepted in `<img src>`, `background-image` (in `write_html`, `update_styles`, `create_artboard` styles). The prompt and options are read from the URL the way the guide describes. `paper-gen://` is accepted on input as an alias (as S-22 does for assets) and never output.
2. Generation runs in the background through the provider chosen in Q-9, with the user's own API key, stored in the OS keychain and set in a settings popover. With no key, the layer shows a placeholder and the tool result says how to add one.
3. While generating, the layer shows a placeholder with a progress state on the canvas. When done, the image is saved into the file's assets (not as a remote URL) and the layer's URL is replaced by it, as one undo step.
4. `get_node_info` reports `imageGeneration: { status: processing | ready | error, output: raster }` for a layer with a generated image, so agents can poll.
5. `get_guide({ topic: "image-generation" })` returns our own guide: URL format, prompt tips, sizes, and when to use it (only when the user asks).
6. Failures (bad key, provider error, content refusal) show on the layer and in `get_node_info` with the provider's message.

## Out of scope
SVG generation, image editing or inpainting, video, generating without a user key.

## Acceptance checks
- With a test provider stub, `write_html` with an `opendraw-gen://` image shows a placeholder, `get_node_info` reports processing, then ready, and the image renders on the canvas and in `get_screenshot`.
- The generated image is stored in the file and still shows after a restart with the network off.
- With no key, the tool result explains how to add one and the layer shows a placeholder.
- `get_guide("image-generation")` returns the guide.
