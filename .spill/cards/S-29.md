## Purpose
Run OpenDraw as a server that a team can sign in to, copied from doop's server (server/auth.ts, server/env.ts, server/db, server/mailer.ts, server/storage.ts, Dockerfile, docker-compose.yml). The desktop app stays local with no accounts unless it is pointed at a server.

## Requirements
1. Server mode: one process serves the editor in the browser, the document API and the MCP endpoint. It starts with `bun run start` or the Docker image; `GET /healthz` answers. Without `DATABASE_URL` it uses embedded PGlite under `data/`; with it, Postgres.
2. Accounts are off by default. They turn on only in server mode, where every page and API call needs a signed-in account (better-auth, email and password). The desktop app with no server configured shows no sign-in and works on local files as today.
3. Sign-up, sign-in, sign-out, email verification and password reset work as in doop: with SMTP set, verification is required and reset links are emailed; without it, emails print to the server log. `SIGNUP_EMAIL_DOMAINS` limits sign-up to listed domains.
4. Files live in the database in server mode, in the same document format as .opendraw files; assets go to `data/assets` or an S3-compatible bucket when configured.
5. Configuration is validated once at boot (doop's server/env.ts pattern): `BETTER_AUTH_SECRET` and `BETTER_AUTH_URL` are required in production; a missing one stops the server with a message naming it.
6. An account page: name, email, password change, and delete account.

## Out of scope
Social sign-in (Google, Microsoft, Apple) and SSO, workspaces and billing, instance admins and "view as", analytics, rate-limit tuning beyond doop's defaults.

## Acceptance checks
- Start the server with no env beyond the two required ones: sign up, verify through the logged link, sign in, create a file, sign out; a signed-out request to the file API gets 401.
- The desktop app with no server configured opens straight to the editor with no sign-in.
- The Docker image builds and `/healthz` answers.
- Missing `BETTER_AUTH_SECRET` in production stops the server naming the variable.
