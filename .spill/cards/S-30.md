## Purpose
Let a file's owner bring people in, copied from doop's access model (server/access.ts, shared/canvasRole.ts, src/components/ShareModal.tsx). Needs server mode with accounts.

## Requirements
1. Files are private by default: only the owner and invited people can open one.
2. Share dialog: invite by email (existing accounts get access at once; an unknown address gets an emailed invite that grants access on sign-up), list who has access with their role, change or remove a role. Roles: viewer, commenter, editor, owner.
3. Link sharing: what anyone signed in with the link gets: nothing (default), view, comment or edit.
4. One access check (doop's server/access.ts) guards the editor, the document API and MCP, so an agent connected by a user has exactly that user's access.
5. A viewer or commenter sees a badge and cannot edit; a commenter can comment.
6. The home view lists the user's own files and files shared with them.
7. How two people editing the same file at once stay consistent follows Q-13.

## Out of scope
Live cursors, presence and follow mode (multiplayer is left out), workspaces, the community gallery.

## Acceptance checks
- Owner invites a second account as viewer: it opens the file read-only with a badge; as editor it can edit; removed, it gets 403.
- An emailed invite to a new address grants access after that address signs up.
- Link set to comment: another signed-in account can comment but not edit.
- An agent connected by a viewer cannot write (MCP returns an access error).
